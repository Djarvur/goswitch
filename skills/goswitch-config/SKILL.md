# Настройка goswitch

Справочник для AI-ассистентов: что настраивается в goswitch и как. Конфиг —
один YAML-файл, путь демону передаётся флагом `-config` (по умолчанию
`goswitchd` работает на встроенных дефолтах):

```sh
goswitchd -config ~/.config/goswitch/goswitch.yaml
```

Правки вступают в силу без перезапуска демона (горячая перезагрузка).
Невалидная правка — опечатка, значение вне диапазона, неизвестный ключ,
битый regex — отвергается **целиком**: демон продолжает работать на
последней валидной конфигурации и пишет WARN в журнал, а причина видна в
`goswitchctl status` (`config_error=`). Полный канон схемы и поведения —
`docs/CONFIG.md`; таблица ключей внизу этого файла генерируется из него и
сверяется CI-гейтом (D-8-10).

## Процедуры

### Включить или выключить автокоррекцию

1. Откройте конфиг (путь из `systemctl --user cat goswitchd`, флаг
   `-config`).
2. Поставьте `autocorrect.enabled: true` (выключение — `false`).
3. При включении добавьте явные пороги: `autocorrect.min_word_len`,
   `autocorrect.trigram_margin`, `autocorrect.trigram_floor`.
   Включённая секция с нулевыми порогами — громкий отказ загрузки, а не
   вырожденный детектор.
4. Сохраните файл — правка подхватывается горячей перезагрузкой, перезапуск
   демона не нужен.
5. Тумблер «Автокоррекция» в трей-меню переключает тот же ключ и сохраняет
   его в конфиг (выбор переживает перезапуск).

### Чёрный список приложений (не исправлять здесь никогда)

1. В список `autocorrect.apps_blocklist` добавьте regex-паттерны (RE2):
   матчинг подстрокой (`chromium` находит `org.chromium.Chromium`),
   анкеровка `^…$` — явная, регистр чувствителен, порядок незначим.
2. Совпавший паттерн запрещает коррекцию в этом приложении; пустой список
   ничего не запрещает.
3. Потолок — 64 паттерна; пустой или битый паттерн — отказ загрузки всего
   файла.

### Переназначить хоткеи

1. `hotkeys.tap_key` — клавиша тапов: одинарный тап переключает раскладку,
   двойной исправляет слово, тройной — фразу. Только «голая» клавиша, без
   модификаторов.
2. `hotkeys.word_layout_combo` — сочетание «исправить слово, затем
   переключить раскладку».
3. `hotkeys.mode_switch_chord` — прямое переключение режима скрипта;
   пусто = выключено. Дефолт `super+space` работает потому, что
   `goswitchctl install` перехватывает биндинг GNOME switch-input-source.
4. Имена клавиш и модификаторов — из закрытой таблицы (раздел «Имена
   привязок» в `docs/CONFIG.md`); сочетания собираются через `+`, клавиша —
   последняя, остальное — удерживаемые модификаторы.

### Звуки

1. `sound.enabled` — звуки переключения и автокоррекции; отсутствующая
   секция или ключ читается как включено (дефолт владельца). Тумблер «Звук»
   трей-меню сохраняется сюда.
2. `sound.autocorrect_event` — ОТДЕЛЬНЫЙ тон на срабатывания
   автокоррекции: имя события звуковой темы, играется через
   `canberra-gtk-play` (фолбэк — `paplay`). Пустое значение читается как
   встроенный дефолт. Тон флипа — фиксированное событие `bell`, он не
   настраивается.

### a11y-магия приложений

1. В список `a11y.apps` добавьте regex-паттерны приложений (правила те же,
   что у blocklist: подстрока, явная анкеровка, регистр, потолок 64) и
   поставьте `a11y.enabled: true`. Секция активна при `enabled: true` И
   непустом списке.
2. При старте и на каждой горячей перезагрузке демон приведёт к `true` две
   ручки окружения: gsettings-ключ
   `org.gnome.desktop.interface toolkit-accessibility` и свойство
   `org.a11y.Status.IsEnabled` шины доступности. Применение идемпотентно:
   ключ, уже равный `true`, не переписывается.
3. Приложения читают ключ при СВОЁМ следующем запуске — перезапустите
   приложение из списка; у уже работающего приложения accessibility-дерево
   не появится (Chromium/Electron проверяют ключ одноразово при старте).
4. Снятие ключа демоном не предусмотрено: удаление приложения из списка и
   `enabled: false` ключ не выключают — вручную включённое состояние
   неотличимо от включённого goswitch. Единственный путь отката —
   `goswitchctl uninstall`: пред-установочное значение снимается в
   `install-state.json` при установке и восстанавливается при удалении
   (на старых установках без этого поля ключ остаётся как есть).

## Диагностика

### goswitchctl status

`goswitchctl status` печатает строки формата `key=value`: режим, счётчики,
состояние конфига. При ошибке конфигурации последней идёт строка
`config_error=…` — начинайте разбор с неё.

### Журнал

`journalctl --user -u goswitchd -f` — журнал демона (systemd user unit
`goswitchd.service`, структурированный slog). Отвергнутая правка конфига
видна как WARN `config reload rejected`; путь конфига, применённое окно
тапов и статус валидности логируются, но содержимое конфига, набранное и
исправленное слово — никогда (автокоррекция сообщает только счётчики и
слаги причин).

### Известные ограничения

- **Жесты ничего не делают в GTK4-приложении.** Известное платформенное
  ограничение GNOME 46 GTK4-Wayland: переданные события клавиш доходят до
  приложения, но GTK4-виджеты на них не реагируют; приложения семейства
  Chromium применяют их нормально.
- **Терминалы и приложения без accessibility-дерева молчат.** Демону
  недоступна роль текстового поля — сверка невозможна, слой молчит
  (fail-closed). Для Electron/Chromium-приложений лечится секцией `a11y`
  плюс перезапуском приложения.
- **Поля паролей не трогаются никогда** (GTK4-роль 40; у GTK3-полей роль
  61 неоднозначна — в известном приложении коррекция возможна, ограничение
  AT-SPI, принятое владельцем; неизвестное приложение молчит).
- **a11y-магия — restart-семантика:** уже работающее приложение ключ не
  подхватит; применяется «при следующем запуске приложения».
