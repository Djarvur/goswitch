# Техническое задание: goswitch — корректор раскладки и введённого текста для GNOME Wayland

> Статус: DRAFT v0.9 (фаза 1 SDD — создание спецификации; противоречия и открытые вопросы помечены `[Q]`)
> Владелец: Daniel Podolsky (@onokonem, Djarvur)
> Исполнитель: Hermes Agent

---

## 1. Проблема

На GNOME Wayland (Ubuntu 24.04, T2 MacBook Pro) отсутствует полноценный аналог Punto
Switcher: исправление текста, набранного не в той раскладке, и ручное переключение
раскладки удобными горячими клавишами. Существующие решения не покрывают потребность:

| Инструмент | Что не так |
|---|---|
| WaylandSwitcher (Nim) | Работает, но: форк чужого кода; чтение evdev напрямую несовместимо с ремапперами уровня keyd/xremap (EVIOCGRAB монополен); нет автотестов; бинарная поставка без исходной экосистемы |
| keyd / xremap | Только ремап клавиш; нет буферизации текста и коррекции; монополизируют клавиатуру |
| IBus-engine (Python) | Правильный уровень (не конфликтует по построению), но прежний прототип не доведён |
| xneur, PUNTO и пр. | Мертвы или неработоспособны на GNOME Wayland |

Цель — написать **свой** корректор на **Go**, по SDD, с **автоматизированным
тестированием полного цикла** (пользователь не участвует в тестировании).

## 2. Терминология и классы задач

1. **Коррекция по горячей клавише** (обязательно): перепечатать последнее слово /
   всю фразу / выделенный текст в другой раскладке.
2. **Переключение раскладки** (обязательно): по горячей клавише, с возможностью
   «переключить и перепечатать» одной комбинацией.
3. **Автокоррекция** (возвращена в объём как содержимое milestone v1.1.0 — решение
   владельца от 2026-09-27; см. §11 и ADR-007): молчаливое исправление набранного слова
   без команды пользователя — только opt-in (default off), только с white/black list
   по классам окон.

## 3. Архитектурное решение (утверждённые принципы)

### 3.1 Инъекция текста — через IBus engine, НЕ через uinput

Демон = **IBus input method engine** (Go, через D-Bus `org.freedesktop.IBus`).
IBus-движок:
- видит клавиатурные события до приложений, на уровне метода ввода — не конфликтует
  с evdev-ремапперами (keyd/xremap могут жить рядом, каждое на своём слое);
- умеет **коммитить текст** в поле ввода напрямую (`commit_text`), чем заменяет
  хрупкую эмуляцию «Backspace ×N + перепечатывание» через uinput;
- не требует grab клавиатуры: обычный набор идёт транзитом (forward), движок
  вмешивается только по горячей клавише.

Следствия (зафиксировать как аксиомы дизайна):
- Коррекция работает в любом поле ввода GTK/Qt/Chromium/Electron, где активен IBus.
- В терминалах, где IBus-предкоммит не применим, горячие клавиши коррекции
  обрабатываются, но механизм вставки — см. §6.4 `[Q]`.

### 3.2 Один демон — все функции

`goswitchd` — единый процесс: IBus engine + D-Bus сервис + наблюдение за раскладкой.

### 3.3 SDD-процесс

Работа ведётся по трёхфазной модели SDD (см. SKILL spec-driven-development):
фаза 1 — настоящее ТЗ и вопросы; фаза 2 — доработка спеки (код не открывается);
фаза 3 — реализация по спеке с гейтами качества. Изменения требований — через
spec-delta, а не правкой кода «по мотивам».

## 4. Функциональные требования

### 4.1 Горячие клавиши (дефолт, настраивается)

| Действие | Дефолт |
|---|---|
| Исправить последнее слово | `Double right shift` |
| Исправить всю фразу после курсора | `Triple right shift` |
| Исправить выделенный текст | `Double right shift` при активном выделении |
| Переключить раскладку | `Right shift` |
| Переключить раскладку (сочетание) | Super+Space (goswitch перехватывает биндинг GNOME switch-input-source при установке) |
| Исправить слово и переключить раскладку | `Shift+RightCtrl` `[Q: конфликтует с прошлым опытом дублирования]` |

Все комбинации переназначаются в YAML-конфиге без перезапуска (hot reload).

В идеале должны использоватья клавиатурные биндинги свитчера Caramba.

### 4.2 Направления коррекции

- EN→RU и RU→EN по позиции клавиш (ЙЦУКЕН↔QWERTY) — ПОЛНАЯ конвертация по физическим клавишам (директива владельца 2026-09-28 «изучи раскладку и сделай все как надо», суперседирует D-14 и allow-set 2026-09-27): преобразуется КАЖДЫЙ знак таблицы — буквы, скобочный ряд, запятая (клавиша «б»), точка (клавиша «ю»), «?» (русская запятая на Shift+/) и оба уровня Shift; отображение биективно — те же физические клавиши в другом режиме дают тот же текст. Знаки, отсутствующие в таблице (пробел), едут без изменений; буква без записи в таблице отказ всего слова.
- Автоопределение направления по составу буфера (какой раскладки больше букв).
- Смешанный текст: корректируется только часть, набранная не той раскладкой,
  относительно последней использованной. `[Q: определить точную семантику]`

### 4.3 Поведение коррекции

- Замена без визуального «прыжка»: `commit_text` заменяет ровно диапазон
  неверного текста `[Q: подтвердить возможность замены диапазона в IBus API]`.
- Сохранение регистра: `GHBDTN`→`ПРИВЕТ`, `Ghbdtn`→`Привет`, `ghbdtn`→`привет`.
- Не трогать: URL, e-mail, пути, hex-строки — по настраиваемым эвристикам (v2).
- После успешной коррекции, изменившей текст (слово, фраза ИЛИ ВЫДЕЛЕНИЕ — расширение по отчёту владельца 2026-09-28), внутренний режим скрипта переключается вслед за коррекцией — строго после записи о завершении (порядок D-36); по умолчанию включено, отключается ключом `correction.flip_after_correction`; исход «done без изменений» и любой отказ раскладку никогда не переключают (решение владельца, 2026-09-27).
- Буфер «чистится» по: Enter, Tab, смена фокуса окна, Escape. Клик мыши триггером не является (на уровне метода ввода не наблюдаем). Перед любой коррекцией буфер в обязательном порядке сверяется с текстом непосредственно перед курсором (surrounding text); при расхождении коррекция молча отменяется («abort, не мусорить»). Там, где приложение полностью сообщает surrounding text, скачок позиции курсора, не объяснимый клавиатурным вводом, сбрасывает буфер (best-effort).

### 4.4 Интеграция с окружением

- Чтение/установка текущей раскладки через GNOME (`org.gnome.desktop.input-sources`).
- Работает поверх любого IM-стека, который не перехватывает IBus (дефолт Ubuntu).
- Совместимость с keyd/xremap на клавиатуре — обязательна (разные слои).

### 4.5 Коррекция клавиатурных макросов

- Замена сочетаний Super+Буква на Ctrl+Буква на лету в определенных приложениях:
  нужно для того, чтобы системно заменить Ctrl+C, например, на Super+C,
  чтобы одно и то же сочетание управляло буфером обмена единообразно во всех приложениях
  (в терминале, например, Ctrl+C зянят).

## 5. Нефункциональные требования

- Язык: Go ≥ 1.23, только stdlib + `godbus/dbus` + минимальные зависимости.
- Демон без root: членство в группе доступа IBus-сокета; systemd **user** unit.
- Производительность: действия без ожидания — < 50 мс; действия Right Shift — не дольше окна различения (дефолт 300 мс, настраивается); память < 50 МБ.
- Логи: структура, уровни; debug-режим с трассировкой клавиш.
- Установка: `go install` (bin + unit + engine-регистрация в IBus), бинарник из github releases.

## 6. Открытые вопросы (фаза 2 SDD)

- [Q1] IBus engine на Go: проверить жизнеспособность D-Bus API (_RegisterComponent,
  статус активного движка, перехват горячей клавиши на уровне движка).
- [Q2] Замена диапазона текста вместо полного перекоммита — какая точность
  доступна через IBus + GTK IM-модуль?
- [Q3] Терминалы (wezterm): работает ли IBus-engine? Если нет — fallback:
  wl-clipboard + эмуляция вставки, или отказ от коррекции в терминалах v1.
- [Q4] Перехват горячих клавиш (Pause): на уровне IBus движка или отдельный
  XKB-слой? Сравнить задержку и надёжность.
- [Q5] Поведение при включённом IBus-движке для не-латинских/не-кириллических
  раскладок (немецкий и т.п.) — пропуск без обработки?
- [Q6] Схема автозапуска: systemd user unit + ibus-daemon restart после установки.

## 7. Автоматизированное тестирование (критическое требование)

Полный цикл без участия человека. Два уровня:

### 7.1 Unit / golden (CI, headless)
- Раскладочные таблицы: EN↔RU по позициям, регистры, знаки.
- Детектор направления на корпусе слов.
- Парсер конфига, hot reload.
- Чистая логика буфера: подача событий (клавиша→буфер), фиксация решений.

### 7.2 End-to-end (машина с сессией GNOME, автоматом)
Стенд-скрипт (Go + shell), который:
1. Поднимает чистый контекст: активирует окно редактора через AT-SPI/WM.
2. Инжектирует нажатия **физическим путём** (ydotool/uinput) — тот же путь,
   что у живой клавиатуры, проходит через все слои.
3. Читает результат из поля редактора через AT-SPI.
4. Сравнивает с ожиданием; матрица кейсов в YAML (ввод → ожидание):
   `ghbdtn`+Pause→`привет`; `GHBDTN`+Pause→`ПРИВЕТ`; фразы; выделение;
   смешанный текст; разные приложения (gnome-text-editor, gedit, Chrome).
5. Печатает отчёт PASS/FAIL по кейсам, код выхода ≠ 0 при падении.

Приёмка фазы 3 = зелёная матрица e2e + ручная приёмка владельцем (одна сессия).

### 7.3 Стендовые требования
- Утилиты: `ydotool` (или собственный инжектор на uinput), `at-spi` (python3-gi).
- Известная ловушка: тест обязан сам активировать целевое окно перед кейсом
  (фокус непредсказуем при ручном использовании машины параллельно с прогоном).

## 8. Поставочные артефакты

- `cmd/goswitchd` — демон.
- `cmd/goswitchctl` — CLI-управление (статус, перечитать конфиг, коррекнуть принудительно).
- `engine/` — IBus engine-адаптер.
- `layouts/` — таблицы раскладок + генератор (go:generate).
- `test/e2e/` — стенд из §7.2.
- `docs/` — это ТЗ, ADR по открытым вопросам, инструкция установки.
- GitHub Actions: unit на каждый push; e2e — manual dispatch (требует GNOME-раннера).

## 11. Решение по автокоррекции (записано, не оспаривается)

Автокоррекция отвергнута владельцем осознанно (пароли, код, невозможность
исключений по приложениям на Wayland). Если когда-либо вернёмся — только
отдельной опцией, default off, с white/black list по классам окон.

     в объём как содержимое milestone v1.1.0. Старый вердикт сохранён

Решение владельца (2026-09-27, D-51): автокоррекция возвращена строго на
предписанных ею же условиях — отдельной опцией, default off, с white/black
list по классам окон. Она открывает milestone v1.1.0 (в объём v1 не входит).
Механика возврата — ADR-007: гибридный детектор (словарный путь + триграммный
fallback), роль AT-SPI как источник решения — живой GetRole в момент решения,
fail-closed политика (любое «неизвестно» → молчание).

<!-- Правка закреплённого решения — решение владельца 2026-10-04
     (фаза 07 «Меню v2 и чёрный список автокоррекции», ревизия D-53):
     белый список заменён чёрным; прежние вердикты сохранены выше
     дословно как аудит-трейл. -->

Решение владельца (2026-10-04, ревизия D-53): автокоррекция исправляет
тогда и только тогда, когда включена (`enabled`), полевой role-гейт
пропускает (текстовый ввод; пароли и терминалы — никогда),
surrounding-text применим, вердикт детектора уверен, длина слова в норме
и приложение НЕ совпало с чёрным списком `autocorrect.apps_blocklist`.
Ключ — список regex-паттернов (RE2): матчинг подстрокой, анкеровка
`^…$` явная; совпадение любого паттерна = запрет автокоррекции.
Неизвестная идентичность приложения НЕ запрет — blocklist не может
исключить невидимое; полевой role-гейт остаётся фильтром безопасности.
Прежнее правило «неизвестно → молчание» снято только для идентичности
приложения — для роли, capabilities и вердикта детектора fail-closed
сохранено. Белый список `autocorrect.apps` удаляется из схемы, кода,
корпуса и документации (миграция — docs/CONFIG.md). Confirm-гейт сверяет
чёрный список ТЕКУЩЕГО приложения; равенство «приложение арма /
подтверждения» удаляется — перенос фокуса ловит payload-stale (сверка
буфера). Ручная коррекция (двойной Shift, фраза, выделение) blocklist
не ограничивается — явное действие пользователя. Default off сохранён
(D-54: `enabled: false`, пустой blocklist). Управление — меню v2 трея с
тумблером, персистящим в конфиг. Механика ревизии — amendment ADR-007
(датированное дополнение, не новый ADR).

Решение владельца (2026-10-04, «Звуки при переключении», отдельный пункт
этой же ревизии): секция `sound` в конфиге — `enabled` (включён по
умолчанию) и отдельное событие тона на срабатывание автокоррекции. Звук
сопровождает ЛЮБОЙ флип языка (Shift, пункты меню EN/RU); срабатывание
автокоррекции — отдельный тон. Воспроизведение — субпроцесс
(canberra-gtk-play предпочтительно, paplay с комплектными тонами как
фолбэк); отказ воспроизведения — только WARN, никогда не блокирует
переключение (звук best-effort по природе). Управление — тумблер «Звук»
в меню с persist — по утверждённому каноническому макету меню (287999c):
«Звук» следует за тумблером автокоррекции.
