# ADR-004: Триггеры сброса буфера набора

## Status

Accepted — гейт M0 (ревью владельца, план 01-04 Task 3) пройден 2026-09-10:
владелец утвердил ADR-пак ответом «утверждено». Spec-delta применён к §4.3
docs/SPEC.md. До M0 носил статус Proposed.

## Context

Спека §4.3 требует: «Буфер "чистится" по: Enter, Tab, клик мыши, смена фокуса
окна, Escape». Триггер «клик мыши» на уровне метода ввода **невыполним**:
клик не проходит через IBus — движок событий мыши не получает вообще
(архитектурное следствие §3.1). Требование в текущем виде описывает
ненаблюдаемое событие.

Решение CONTEXT фазы 01 (дословно):

> **D-06:** «Клик мыши» убирается из триггеров сброса буфера (невыполнимо на
> уровне метода ввода — клик не доходит до IBus). Вместо него два механизма:
> (1) обязательная сверка перед коррекцией — буфер должен совпадать с текстом
> непосредственно перед курсором (surrounding text); не совпало → молча
> ничего не делать («abort, не мусорить»); (2) best-effort сброс буфера по
> скачку позиции курсора в surrounding text там, где приложение его полностью
> сообщает. Оформить как spec-delta к §4.3 спеки. — **Reversibility:**
> reversible

## Decision

1. **Клик мыши исключён** из триггеров сброса буфера.
2. Остаются наблюдаемые на уровне IME триггеры: Enter, Tab, Escape, смена
   фокуса окна (FocusOut), Reset от ibus-daemon.
3. Добавляются два механизма из D-06:
   - **Обязательная сверка перед коррекцией.** Непосредственно перед
     исправлением движок сверяет накопленный буфер с текстом прямо перед
     курсором (surrounding text, `SetSurroundingText` + позиция курсора).
     Любое расхождение → молча ничего не делать — принцип «abort, не
     мусорить»: лучше пропустить коррекцию, чем испортить поле. Это
     защищает и от класса «клик мышью переместил курсор»: невидимый
     триггер заменён видимой сверкой последствия.
   - **Best-effort сброс по скачку курсора.** Там, где приложение полностью
     сообщает surrounding text, движение позиции курсора, не объяснимое
     вводом с клавиатуры (прыжок влево/вправо за пределы последнего
     введённого), сбрасывает буфер. Где surrounding text не сообщается
     (бит 1<<5 отсутствует) — механизм молча не работает, остаётся сверка
     из пункта выше и явные триггеры.

Spec-delta к §4.3 спеки (готовый текст, применяется после утверждения
владельцем на гейте M0):

> Буфер «чистится» по: Enter, Tab, смена фокуса окна, Escape. Клик мыши
> триггером не является (на уровне метода ввода не наблюдаем). Перед любой
> коррекцией буфер в обязательном порядке сверяется с текстом
> непосредственно перед курсором (surrounding text); при расхождении
> коррекция молча отменяется («abort, не мусорить»). Там, где приложение
> полностью сообщает surrounding text, скачок позиции курсора, не
> объяснимый клавиатурным вводом, сбрасывает буфер (best-effort).

## Consequences

- CORR-09 реализуем без нарушений архитектуры: все триггеры наблюдаемы
  движком, ни один не требует событий вне IBus.
- Сверка перед коррекцией — обязательная часть протокола Фазы 2; она же
  закрывает класс рассинхронизаций, который «клик мыши» закрывал в спеке.
- В полях без surrounding text (часть Chromium-класса, терминалы) сброс
  по скачку недоступен — поведение документировано как деградация, а не
  как ошибка.
- e2e-кейсы Фазы 2 получают сцену «переместить курсор кликом, затем
  корректировать» с ожиданием «ничего не произошло» — именно через сверку,
  а не через наблюдение клика.

## Reversibility

Оценка CONTEXT дословно: **reversible**. Механизмы D-06 не требуют
пользовательского контракта: смена не переучивает пользователя; до
реализации Фазы 2 меняется только текст спеки.
