# ADR-005: MACR-01 — механизм замены Super+Буква → Ctrl+Буква по приложениям

## Status

Proposed — механизм утверждается владельцем на гейте M0 (план 01-04).
**Судьба MACR-01 уже решена владельцем (D-12): в v1, реализация внутри
goswitch** — этот ADR решает только МЕХАНИЗМ: как движок определяет
«определённые приложения» и как ведёт себя там, где GNOME перехватывает
Super+Буква раньше метода ввода. Никакого кода MACR-01 в Фазе 1 нет и не
планируется — реализация в Фазе 3.

## Context

Требование SPEC §4.4: заменять сочетания Super+Буква на Ctrl+Буква на лету в
определённых приложениях, чтобы одно и то же сочетание управляло буфером
обмена единообразно во всех приложениях (в терминале Ctrl+C занят).

Решение владельца (CONTEXT фазы 01, дословно):

> **D-12 (MACR-01, закрыто 2026-09-10 со слов владельца):** Замена
> Super+Буква → Ctrl+Буква остаётся в v1 и реализуется **внутри goswitch**.
> Обоснование владельца: «идея этого приложения — в упрощении конфигурации;
> настройка keyd оказалась сложна и ненадёжна; то, что можно было бы делать
> на keyd, будем делать на goswitch». ADR-005 фазы 1 решает не судьбу (судьба
> решена: v1), а **механизм**: как определять «определённые приложения» на
> уровне движка (кандидаты: FocusIn-хинты клиента, глобальные правила +
> опциональные списки приложений, AT-SPI-наблюдатель) и как вести себя там,
> где Super перехватывается GNOME раньше метода ввода. Прежняя рекомендация
> «вынести в v2 + рецепт keyd в доки» ОТКЛОНЕНА; отложенная идея «рецепт
> keyd» снята. — **Reversibility:** costly — требование закреплено в
> v1-объёме, механизм входит в ADR-005 и фазу 3

Спека §4.4 оставляет открытым и второй вопрос: GNOME/mutter биндит часть
Super+Буква на свои действия (обзор, скриншоты и т.п.) — эти комбинации до
метода ввода не доходят, и молчаливый провал подмены был бы скрытым
несоответствием требованию.

## Decision

### (a) Определение «определённых приложений»

Кандидаты оцениваются по наблюдаемости на уровне движка (сверка с картой
D-Bus IBus 1.5.29 из исследования фазы 01 — живая интроспекция на целевой
машине):

| Кандидат | Вердикт | Обоснование |
|---|---|---|
| FocusIn-хинты клиента | **Отклонён** | Карта D-Bus 1.5.29: `FocusIn()` не имеет аргументов вовсе — ни имени клиента, ни pid, ни хинтов приходят с событием. Хинты неоткуда читать. |
| Глобальные правила + опциональные per-app списки (YAML) | **Основной механизм** | Определяется конфигурацией, детерминирован, не добавляет рантайм-зависимостей; идентичность приложения нужна только для опциональных списков-исключений. |
| AT-SPI-наблюдатель по D-Bus | **Fallback-источник идентичности** | AT-SPI отдаёт приложение сфокусированного окна (уже доказано хелпером e2e-стенда на этой машине); подключается к a11y-шине только когда в конфиге есть per-app списки. |

Итог: **основной механизм — глобальные правила + опциональные per-app списки
в YAML; идентичность приложения для списков — AT-SPI-наблюдатель**;
FocusIn-хинты отклонены как не существующие на проводке 1.5.29. Деградация
наблюдаема: если a11y-шина недоступна, per-app списки перестают различаться —
движок логирует WARN «app-identity unavailable» и применяет только глобальные
правила (документированная деградация, не молчаливый провал).

### (b) Перехват Super+Буква GNOME раньше IME — лестница деградации

1. **Обнаружение.** Модификатор Super сам по себе до движка доходит (press/
   release наблюдаются в `ProcessKeyEvent`), а связанная буква — нет. Движок
   эмпирически детектирует «Super вниз → (нет буквенной клавиши) → Super
   вверх» для сконфигурированных комбинаций: комбинация потреблена уровнем
   GNOME (mutter keybinding) раньше метода ввода.
2. **Фиксация.** Событие пишется в структурный лог (WARN
   `super-combo-consumed-upstream`, клавиша, счётчик) и отображается в
   `goswitchctl` как «комбинация недоступна: перехвачена GNOME». Это
   ограничение GNOME фиксируется в документации как известное.
3. **Fallback для пользователя.** Для перехваченных комбинаций YAML-конфиг
   позволяет назначить альтернативный модификатор замены (например
   Hyper+Буква или другой префикс) — значение по умолчанию не вводится до
   живой проверки Фазы 3, чтобы не плодить второй неявный контракт.

Лестница гарантирует: ни один случай перехвата не остаётся невидимым —
лог, статус в ctl и конфигурируемый обход.

## Consequences

- Объём Фазы 3: реализация подмены (перехват Super+Буква в `ProcessKeyEvent`,
  генерация Ctrl+Буква через `ForwardKeyEvent`), AT-SPI-наблюдатель как
  опциональный компонент, `goswitchctl`-видимость перехваченных комбинаций.
- Формат YAML-конфига (Фаза 3) обязан вместить: глобальный вкл/выкл MACR,
  per-app списки (имена приложений как их видит AT-SPI), альтернативные
  модификаторы для перехваченных комбинаций.
- AT-SPI-зависимость опциональна и подключается только при наличии per-app
  списков — базовая функция MACR (глобальные правила) работает без a11y.
- В Фазе 1 нет ни строки кода MACR-01 — только этот механизм; судебное
  решение (D-12) цитировано выше и пересмотру не подлежит.

## Reversibility

Оценка CONTEXT дословно: **costly** — «требование закреплено в v1-объёме,
механизм входит в ADR-005 и фазу 3». Сам выбор механизма (глобальные правила
+ AT-SPI fallback) обратим до реализации Фазы 3; после — смена потребует
миграции конфигурации пользователей.
