<objective>
Engine self-reactivation: after every successful component (re)registration, goswitchd re-activates its own engine as the global IBus input source — but only when goswitch already owns the current GNOME input source. This fixes the live-verified defect (2026-09-27) where a daemon restart (`systemctl --user restart goswitchd`, unit `Restart=on-failure`) re-registered the component yet left nothing activating the engine, so every keystroke silently bypassed goswitch through plain XKB until a human ran `ibus engine goswitch-en` by hand.

Purpose: the daemon is the sole supervisor of its own activation; a restart must restore the exact input state the user had (per D-40 single-owner semantics), unattended — the UAT gate (Phase 4) and the nightly D-48 pipeline restart the daemon, and today each restart silently kills correction until manual intervention.

Output: new `internal/activate` package (ownership check + activation + bounded retry, never fatal), a `PostRegister` hook in `engine.Config` fired after registration, daemon wiring, README recovery contract (EN + RU).

The related defect where Super+Space with a single input source disables the engine context is DOCUMENTED ONLY in this task (remedy: `ibus engine goswitch-en`), per the diagnosis — no live detection/fix for it.
</objective>
