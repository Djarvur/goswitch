# Project Retrospective

*A living document updated after each milestone. Lessons feed forward into future planning.*

## Milestone: v1.0.0 — MVP

**Shipped:** 2026-10-08
**Phases:** 8 | **Plans:** 61 | **Timeline:** 2026-09-10 → 2026-10-08 (28 дней), релизы v1.0.0 (2026-09-16) и v1.1.0 (2026-10-06) внутри вехи

### What Was Built
- IBus engine на чистом Go (godbus-wire, без XML и root): коррекция слова/фразы/выделения/смешанного текста, флип раскладки, MACR-перехват, YAML-конфиг с hot reload, goswitchctl
- Установка без root одной командой + selfcheck + полный откат; релизный контур goreleaser; ночной автономный приёмочный гейт D-48 v2
- GNOME-интеграция: нативный трей-индикатор с интерактивным меню, флип через SetGlobalEngine
- Автокоррекция default-off (гибридный детектор: словари 218k + триграммы, role-гейт fail-closed, blocklist regex), звуки через персистентный PulseAudio-стрим, a11y-магия приложений, русский-первый README + golden-синхронный конфиг-skill

### What Worked
- **SDD-дисциплина (спека до кода, D-55)** — все изменения требований (D-51..D-55, ревизии владельца) легли датированными дельтами с аудит-трейлом до коммита кода; ноль споров «что имелось в виду» на ревью
- **Строгий TDD RED→GREEN + зелёная итерация (mise run ci на каждой границе)** — 61/61 планов без красного хвоста; флейки ловились и изолировались, не протаскивались
- **Живой стенд как окончательный арбитр**: юнит-корпус доказывает контракт, живая матрица — поведение. Находка G-2-3 (буфер сбрасывался флипом) прошла сквозь зелёный юнит-корпус и была поймана именно живым прогоном
- **Верификаторы-сабагенты параллельно** — 12 прогонов по milestone-close цепочке сняли stale-фингерпринты всех 8 фаз за одну сессию
- **verdict-записи в STATE.md** (решения/находки с формулировками владельца дословно) — milestone-close реверье опиралось на них, а не на память

### What Was Inefficient
- Milestone-close цепочка верификаций трижды перезапускалась: фингерпринты stale-ели друг друга (фиксы меняли дерево, покрытое ранее верифицированными фазами). Финальные прогоны надо планировать ПОСЛЕ последнего кодового коммита, одной волной
- Дайджесты VERIFICATION.md, посчитанные верификаторами, расходились с каноническим verb'ом (форма/порядок вызова) — 4 ручных пересчёта. Правило «digest только через verb» стоит расширить: «и тем же вызовом, что проверяет закрытие»
- Конкурсный лимит фоновых агентов (3) не был известен заранее — первая волна из 8 верификаторов наполовину погибла
- Средовые флейки (общий session bus, inotify-лимиты, фокус-гонки) съедали прогоны; bus-isolation тестов — накопленный долг

### Patterns Established
- **spec-delta до кода** с дословными формулировками владельца в audit trail
- **Живая матрица как приёмочный контракт**: CASES-FROZEN, перепин только вердиктом владельца
- **WINDOWS-леджер**: каждое расхождение «спека vs факт» нумеруется и закрывается решением владельца, не забывается
- **Стенд герметичен**: кейсы не адоптируют живой конфиг машины (quick 261008-00m)
- **Quick-задачи с валидацией** (--validate: checker + verifier) как форма поставки фич между фазами

### Key Lessons
1. Живой прогон дешевле десяти юнит-тестов на флип-семантику: fixture-only слепые пятна юнит-корпуса реальны (G-2-3), финальная приёмка фичи — на столе
2. Стенд должен быть герметичен к машине, на которой стоит: адоптация живого конфига владельца меняла результаты тестов незаметно
3. Milestone-close верификации запускать строго после заморозки кода; каждый кодовый коммит обесценивает незакрытые фингерпринты
4. Автокоррекция «всё или ничего» не нужна — default-off + blocklist + role-гейт дали безопасную фичу, которую владелец включил сам
5. Фоновые агенты умирают от сна машины и лимитов параллельности — волны по 3, мониторинг уведомлений

### Cost Observations
- Sessions: одна длинная manager-сессия закрытия + 12 фоновых верификаторов + planner/executor/checker quick-задачи
- Notable: 12 ручных UAT-вопросов владельцу сведены к 7 пакетам; основная масса вердиктов — по доказательствам с записанным прецедентом

## Milestone: v1.2 — Терминалы и видимость приложений

**Shipped:** 2026-11-06
**Phases:** 5 | **Plans:** 27 | **Timeline:** 2026-10-08 → 2026-11-06 (29 дней)

### What Was Built
- Терминальный транспорт ADR-008: двойной правой Shift исправляет слово в wezterm и GNOME Terminal через собственный IBus-канал демона (парные press+release форварды + CommitText), CLIPBOARD байт-нетронут, автокоррекция в терминалах под инвариантным запретом (D-55)
- wezterm починен nightly-рецептом (`enable_wayland=true`): XIM-десинк engine→stale-context задокументирован и воспроизведён; владелец на фиксе ежедневно
- Пункт трей-меню «Добавить ИмяПриложения в чёрный список» одним кликом: атомарная запись, потолок 64, честная деградация при невидимой личности
- Рецепты доступности ZCode (desktop-override `--force-renderer-accessibility`, дерево 2→43+ нод) и Telegram (AppArmor-стена snap доказана пробой трёх сборок)
- VM-стенд goswitch-stand — площадка всех живых рядов вехи (venue-вердикт vm-primary в спайк-логе ADR-008)

### What Worked
- **Probe-first**: живая проба до плана (Фазы 12, 13) закрывала гейты вердиктом владельца за один раунд вместо планирования заведомо мёртвых планов
- **Вердикты владельца как закрывающие оракулы** (G-10-1 «осталось»; «строка уже работает машиной слова»; «Задокументировать») — жёсткая экономия раундов
- **Журнальная элиминация как метод** (Orca 22/22): разбор реального журнала дня заменил новую живую пробу на хосте
- **Директива «проверки только на ВМ»** (2026-11-01) — институционализированный обход платформенного UAF

### What Was Inefficient
- Шесть раундов закрытия G-10-1 (10-07…10-18): хост-специфика (T2-ядро, флап фокуса) не воспроизводилась на стенде — каждый раунд рождал новую гипотезу. Хост-дефекты надо было гонять журнальной элиминацией раньше
- UAF at-spi2 уронил сеанс владельца дважды (10-21, 10-31) прежде чем стать директивой; сигнал «полный обход a11y-дерева валит сеанс» был известен с 10-14
- Debug-сессии закрывались по существу, но статус на диске не обновлялся — к milestone-close накопилось 8 открытых записей

### Patterns Established
- **Хост-журнал как оракул**: replay-тесты на дословных журнальных рядах вместо инъекций на хосте
- **Двухразрешительная модель** (ручная — да, авто — нет) как способ безопасной экстензии в опасные поверхности
- **Убить маршрут вместо починки**: DST закрыт гардом по доказательству (wezterm игнорирует, VTE валит mutter)

### Key Lessons
1. Press-only форварды взводят клиентский автоповтор — пары press+release обязательны в любом ключевом реплее (sourcedig, round-6)
2. Средовые дефекты платформы (mutter, at-spi2, T2-ядро) продуктом не «чинятся» — фиксируются гардами, директивами и документацией
3. Владелец — самый дорогой ресурс: один его вердикт решал то, что машине стоило раундов; вопросы готовить одним списком, с доказательствами
4. Фон вехи (закрытие по существу без обновления артефактов) доразбирается на pre-close аудите — статусы стоит закрывать в момент закрытия работы

### Cost Observations
- Sessions: manager-сессии (планирование 10-08, драйв 10-31/11-01/11-03, закрытие 11-06) + executor/verifier волны фаз
- Notable: живые пробы ВМ сняли участие владельца почти во всех машинных рядах — его вердиктов за веху остались единицы
