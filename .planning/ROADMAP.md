### Phase 9: Спайк и дефект wezterm

**Goal**: Переключение раскладки работает в wezterm (ежедневный терминал владельца), а терминальный транспорт закреплён в SPEC и ADR до всякого кода: живой спайк производит verdict-таблицу возможностей, на которой строятся Фазы 10 и 12
**Depends on**: Nothing (первая фаза вехи v1.2; сквозная нумерация после Phase 8 вехи v1.0.0)
**Requirements**: TERM-01, TERM-04
**Success Criteria** (what must be TRUE):

  1. В wezterm на живом столе горячая клавиша переключает раскладку, и последующий ввод даёт символы новой раскладки — два подряд зелёных e2e-оракула (починка: рецепт нативного Wayland-режима первым кандидатом, демонский XIM-обход — фолбэк-ветка)
  2. SPEC несёт датированную spec-delta ревизию (D-55, до кода): слово обязателен, строка feasibility-gated, автокоррекция в терминалах — НИКОГДА; двухразрешительная модель (ручная = да, авто = нет); вето живёт в условии армирования автокоррекции, не в apps_blocklist
  3. ADR-008 (терминальный транспорт) доведён до Accepted на свидетельствах живого спайка, не на веб-источниках
  4. Существует вердикт-таблица возможностей терминалов (caps, доставка ProcessKeyEvent, посадка commit_text, select-чорд → PRIMARY read-back, a11y-идентичность) — она фиксирует kill-критерий строковой растяжки и чорды слова для Фаз 10/12
  5. A11Y-зонд-матрица (минимальный a11y-триггер per-app, env сверен в /proc; AppArmor-стена Telegram snap) выполнена рано/параллельно — вердикты записаны для деградации MENU-идентичности (Фаза 11) и планирования Фазы 13

**Plans**: 2/2 plans executed (09-01 complete; 09-02 halted по решению владельца — ядро-результат и рецепт стоят; 09-03/09-04 superseded: TERM-01 доставлен Фазой 10, A11Y-вердикты существуют рассеянно)

### Phase 10: TERM-слово

**Goal**: Пользователь исправляет слово, набранное не в той раскладке, одним жестом в wezterm и GNOME Terminal — через собственный канал ввода демона (IBus), без внешних инжекторов
**Depends on**: Phase 9 (capability-таблица, ADR-008 Accepted, spec-delta)
**Requirements**: TERM-02
**Success Criteria** (what must be TRUE):

  1. Двойной правый Shift исправляет последнее набранное слово в wezterm (bash и zsh, кириллица, в том числе в середине строки): ghbdtn → привет на живом столе
  2. То же работает в GNOME Terminal (VTE): чтение — собственный буфер нажатий демона; для wezterm при необходимости — primary-выделение по рецепту CopyMode через wl-paste --primary
  3. Замена идёт N×BackSpace-реплеем + commit_text через канал IBus: CLIPBOARD остаётся байт-нетронутым (замороженный e2e-ряд); commit-over-selection и paste-чорды не используются
  4. До первого разрушающего действия (первый ForwardKeyEvent BackSpace) отмена бесплатна и ничего не мутирует; после — verify-сверка при расхождении логирует и останавливается, никогда не «чинит» сама; фокус-переключение между чанками (≤8 клавиш) перечекается
  5. Двухразрешительная модель Фазы 9 живая: замороженные негативные ряды матрицы зелёные — автокоррекция в терминале молчит при работающей ручной коррекции (vim-insert/htop-свидетели)

**Plans**: 16/18 plans executed + 12 gap-closure plans (10-07…10-09 round 1, 10-10…10-12 round 2, round 3: 10-13 blocked крахом gnome-shell / 10-14+10-15 superseded; gap G-10-1) + round-4: 10-16…10-18 (бисекция 2026-10-16: DST — compositor-killer в девственном окне mutter 46.2; Require-receipt для wezterm-класса неформулируем — новый механизм: форварды + pty-drain-доказательства стенда + delivery-метки + флип вне окна + DST-гард безопасности)

### Phase 11: MENU — пункт «в чёрный список»

**Goal**: Пользователь добавляет текущее приложение в чёрный список автокоррекции одним кликом в трей-меню — без ручного редактирования YAML
**Depends on**: Phase 9 (A11Y-зонд: Electron-идентичность существует только после включения a11y); независима от Фаз 10/12 — может меняться с Фазой 10 местами
**Requirements**: MENU-01
**Success Criteria** (what must be TRUE):

  1. В трей-меню виден динамический пункт «Добавить ИмяПриложения в чёрный список» с точным наблюдаемым именем приложения; клик добавляет его в autocorrect.apps_blocklist (regexp.QuoteMeta, без дублей, потолок 64), и автокоррекция в этом приложении замолкает без рестарта демона
  2. Запись атомарна: yaml.Node round-trip с pre-write валидацией + atomic rename — golden-дифф доказывает, что изменилась только новая строка блок-листа, комментарии конфига целы
  3. Когда личность приложения неизвестна (snap, wezterm/winit) — пункт неактивен с объяснением; демон не угадывает и не пишет мусорные паттерны вида :1.NN
  4. Имя приложения с метасимволами regex не ломает конфиг: после записи через меню строгий декодер (KnownFields) принимает файл целиком; при отказе (потолок 64) пользователь получает уведомление из трея

**Plans**: 4/5 plans executed

### Phase 12: TERM-строка

**Goal**: Пользователь исправляет всю набранную строку/фразу в терминале — там и только там, где capability-таблица Фазы 9 подтверждает примитив захвата строки
**Depends on**: Phase 9 (kill-критерий) + Phase 10 (проверенная словесная ступень: та же машина, другой чорд)
**Requirements**: TERM-03
**Success Criteria** (what must be TRUE):

  1. Тройной правый Shift исправляет всю набранную строку в wezterm: курсор возвращается в исходную позицию, суффикс справа от курсора цел (End-нормализация и её побочный эффект задокументированы)
  2. В GNOME Terminal строка работает только если capability-таблица нашла примитив захвата; при kill-критерии (нет выделения с клавиатуры в VTE) область честно сужается до wezterm, и вердикт о сужении — за владельцем
  3. Verify-then-act: расхождение длины выделения с буфером ведёт в определённую ветку (отказ, не угадывание); замороженные негативные ряды автокоррекции остаются зелёными

### Phase 13: A11Y — рецепты Telegram/ZCode

**Goal**: Автокоррекция достижима в ZCode и Telegram через включение доступности в самих приложениях; демон не меняется (решение владельца 2026-10-08) — рецепты, доки, self-check
**Depends on**: Phase 9 (A11Y-зонд-матрица, AppArmor-вердикт); планирование гейтится решением владельца по Telegram (unconfined-сборка vs демон-fallback); исполнение параллелизуемо с Фазами 10-12
**Requirements**: A11Y-01, A11Y-02, A11Y-03
**Success Criteria** (what must be TRUE):

  1. ZCode после user-local `.desktop` override с `--force-renderer-accessibility` и рестарта присутствует в живом AT-SPI-дереве, и автокоррекция работает в его поле ввода (приёмка по живому дереву, не по доке)
  2. Telegram: решение владельца по лестнице (unconfined tarball/deb/flatpak vs демон-fallback) принято и исполнено; при unconfined-пути — входное поле реально видно в AT-SPI-дереве и автокоррекция в нём работает; при демон-fallback — отдельная приёмка с владельцем до закрытия фазы
  3. Рецепты в README/CONFIG.md включают побочные эффекты и границы: плашка Telegram «режим экранного диктора», «флаги Electron применяются только на запуске», restart + self-check в каждом рецепте; README несёт residual-risk заметку (ручная коррекция на скрытых полях копирует в PRIMARY)
  4. К каждому рецепту прилагается user-runnable self-check одной командой
