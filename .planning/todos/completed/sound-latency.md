# Звук: запаздывание тонов флипа/автокоррекции

> **РЕАЛИЗОВАНО 2026-10-06** — quick 261006-squ (gsd-quick --validate: план-чекер 2 итерации,
> верификация 7/7). Спека-дельта SPEC §5/§11 до кода (9bebd67); jfreymuth/pulse v0.1.3 +
> oggvorbis v1.0.5 (+ vorbis v1.0.2 — собственный require oggvorbis); персистентный стрим,
> XDG-резолвер темы, PCM-кэш, синтезированный тон как never-wait фолбэк; mute = ноль соединений,
> включая event-sounds-плечо (пробел найден верификатором, закрыт 38f892a). Проверка владельцем
> на слух — за владельцем (3 пункта в 261006-squ-VERIFICATION.md).

Владелец (2026-10-05, вечер): **«делай»** — переделка звука одобрена, с тремя
требованиями:
1. **Играть звуки из стандартной темы GNOME** — не собственные синтезированные
   тона как основной путь.
2. **Настройки темы получать регулярно**: первый раз на старте демона, дальше
   отслеживать изменения — **асинхронно с самим звучанием**: путь
   воспроизведения никогда не ждёт ни чтения настроек, ни декодирования.
3. **Если звук выключен** (мастер-выключатель) — **не держать соединение со
   звуковым сервером**: подключение ленивое при включении звука, разрыв
   соединения при выключении.

Собственно программирование НЕ начиналось — по указанию владельца («не начинай
собственно программировать, просто зафиксируй беклог») зафиксирован только этот
бэклог. Реализация — quick-таском через gsd-quick, когда владелец скажет.

## Причина (подтверждено замерами, машина владельца, 2026-10-05)

Каждый тон = свежий субпроцесс canberra-gtk-play: старт плеера и инициализация
происходят ПОСЛЕ флипа, этот оверхед и слышен.

- canberra-gtk-play: старт 100–330 мс прогретый (прокси — несуществующее
  событие); bell целиком 0.44–0.51 с; сам демон добавляет 1–3 мс.
- Любой одноразовый плеер того же класса: pw-play 0.16–0.19 с, aplay
  0.19–0.23 с на 60-мс тон. Гипотеза «paplay заметно быстрее — поменять
  предпочтение» замером НЕ подтвердилась (paplay не установлен,
  pulseaudio-utils только в архиве).
- Анатомия canberra (трасса strace): GTK3-бинарь (96 .so, 1040 openat),
  gtk_init сканирует иконочные темы — ~220 мс ради чтения одного имени темы
  (= gsettings `org.gnome.desktop.sound theme-name`); дальше dlopen
  libcanberra-pulse → libpulse → нативный протокол; событие = файл
  `/usr/share/sounds/Yaru/stereo/<имя>.oga` (index.theme:
  `[Sound Theme] Directories=stereo`); vorbis-декодер внутри libcanberra0.
- Per-tone эксперимент (jfreymuth/pulse, свежие коннект+стрим на каждый тон):
  коннект 8–9.5 мс, создание стрима 19–33 мс, старт 4.5–62 мс → звук через
  32–104 мс и скачет; ИТОГО 111–161 мс. Полумера — гипотеза «можно без
  персистентности» опровергнута замером.
- Персистентный стрим (тот же прототип): коннект 3 мс, отправка тона 133 мкс,
  звук ~30 мс (квант стрима) стабильно. Подтверждён как правильный путь.
- Деградация: звуковой сервер недоступен → мгновенный чистый отказ (dial
  unix/tcp), без зависаний — ложится на warn-once-per-episode и ленивое
  переподключение.

## Найденный путь

- **jfreymuth/pulse v0.1.3** — клиент нативного протокола PulseAudio на чистом
  Go (потомок yobert/pulse): MIT, без cgo, ~3.9k LOC (pulse 1275 + proto 2673),
  единственная транзитивная зависимость golang.org/x/sys, релиз август 2026,
  автор jfreymuth (oggvorbis). Прототип на машине владельца: статический
  бинарник (CGO_ENABLED=0), два тона сыграли, underrun нет, ошибок нет.
- **jfreymuth/oggvorbis v1.0.5** — декодер .oga на чистом Go, MIT, тот же
  автор — нужен для воспроизведения звуков темы (Yaru: Ogg Vorbis 44.1 кГц).
- oto v3.5.1 хуже: ~6k LOC + purego, маршрут через ALSA-конфиг;
  mesilliac/pulse-simple мёртв с 2017; cgo libpulse/libcanberra — запрещено
  ограничениями проекта.

## Дизайн-набросок для реализации

- internal/sound: персистентный клиент + персистентный стрим jfreymuth/pulse;
  Reader между тонами отдаёт **тишину** (select/default) — заодно снимает
  дедлок `Start()` (он блокируется до доставки первого буфера серверу; в
  прототипе ловили SIGQUIT-дампом).
- Формат стрима следует за декодированным PCM темы (у Yaru 44.1 кГц стерео);
  при смене формата стрим пересоздаётся.
- Настройки темы: `gsettings get org.gnome.desktop.sound theme-name` на старте
  + `gsettings monitor org.gnome.desktop.sound` для изменений (штатный паттерн
  проекта; надёжность монитора — супервизией, как у индикатора; если monitor
  окажется ненадёжен — периодическое перечитывание, решить при планировании).
- Резолв по XDG Sound Theme spec: index.theme ([Sound Theme] Directories,
  Inherits), поиск в XDG data dirs, файл `<событие>.oga`/`.ogg`/`.wav`.
  События те же: флип = bell (константа), автокоррекция =
  sound.autocorrect_event (горячая, WR-02).
- Декодирование один раз на пару (тема, событие) → кэш PCM в памяти; при
  смене темы пересоздание асинхронно, атомарная подмена кэша. Путь
  воспроизведения никогда не ждёт: кэш не готов (старт демона, смена темы) —
  играется существующий синтезированный тон.
- Выключенный звук: шлюз soundSinkFor() дополнительно ЗАКРЫВАЕТ клиент/стрим —
  при выключенном звуке соединения с сервером нет вовсе (требование
  владельца). Открытый вопрос на планирование: учитывать ли
  `org.gnome.desktop.sound event-sounds` (системное «событийные звуки
  выключены») так же, как мастер-выключатель.
- canberra-gtk-play из дизайна больше не нужен (тот же звуковой сервер —
  фолбэк бессмыслен); schema-события и переключатель «Звук» в трее остаются.
- Инварианты сохраняются: best-effort, никогда не блокирует жест, одна WARN
  на эпизод, пользовательский текст не попадает в логи и аргументы; шов
  SoundSink (Flip / AutoCorrect / SetAutocorrectEvent) не меняется.
- **Spec-delta обязательна**: стек зафиксирован в SPEC (stdlib + godbus +
  минимум зависимостей) — добавление jfreymuth/pulse и jfreymuth/oggvorbis
  идёт через §11.
