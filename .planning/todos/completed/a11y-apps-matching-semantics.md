# a11y.apps: семантика матчинга приложений — решение владельца

Найдено код-ревью фазы 8 (WR-02, 08-REVIEW.md): docs/CONFIG.md и SKILL.md
описывают `a11y.apps` как regex-паттерны приложений (D-8-5, подстрочный матчинг),
но демон нигде не матчит приложения — единственный потребитель списка это
`Active()` (enabled && len(apps)>0), то есть непустой список просто включает
глобальный `toolkit-accessibility` для ВСЕХ приложений.

Контекст, почему так вышло: механизм магии — ГЛОБАЛЬНЫЙ gsettings-ключ, который
Chromium/Electron читает один раз при своём запуске (research 08-RESEARCH.md).
Динамический per-app матчинг (включать ключ только когда сфокусировано
приложение из списка) для запущенных приложений бесполезен — ключ читается на
старте. Список сейчас фактически = «выключатель магии + декларация, каким
приложениям она нужна».

Решение владельца (одно из):
1. **Честные доки** (минимум): переформулировать docs/CONFIG.md + SKILL.md —
   «непустой включённый список включает глобальный ключ; паттерны — декларация
   целевых приложений», затем `mise run skillgen-regen`.
2. **Пер-апп механизм** (крупнее): наблюдение фокуса/запуска приложений из
   списка + user-level .desktop-оверрайды с флагами (D-8-6 оставлял research
   «документируется, вне v1-дифа») — отдельная фаза.
