# Phase 2: Коррекция слова EN↔RU - Context

**Gathered:** 2026-09-11
**Status:** Ready for planning

<domain>
## Phase Boundary

Ядро ценности продукта: двойной тап Right Shift исправляет последнее слово, набранное не в той раскладке (EN↔RU), в любом поле ввода GNOME. Направление определяется автоматически по составу слова, регистр сохраняется посимвольно, замена применяется ровно к диапазону неверного текста по capability ladder (ADR-003) с обязательной сверкой буфера (ADR-004). Приёмка — зелёная e2e-матрица v1 (TEST-04: zenity/GTK + Chromium, полный словесный набор кейсов) на self-hosted GNOME CI-раннере, поднятом уже в этой фазе. Фразы, выделение, смешанный текст в полной семантике, переключение раскладки и YAML-конфиг — Фаза 3; терминальный класс (clipboard-уровень) — отложен во Фазу 3/4.

</domain>

<decisions>
## Implementation Decisions

### Границы слова (диапазон коррекции)
- **D-13:** Слово, уже отделённое пробелом, исправляется двойным тапом (Punto-поведение): буфер помнит последнее слово и после пробела. `ghbdtn <space>` → тап-тап → `привет <space>`. Пробел завершает слово, но не «отправляет» его из буфера. — **Reversibility:** costly — это пользовательский контракт жеста; e2e-кейсы «после пробела» завязаны на него
- **D-14:** Диапазон замены = весь «токен» до границы: примыкающая пунктуация входит. `ghbdtn,` → `привет,` одним диапазоном замены. Принцип владельца: символы, набранные на клавишах, под которыми в раскладке могут стоять буквы, — исправляются; символы с клавиш, где букв быть не может (пробел, Tab и т.п.), — граница слова. Ключи с буквами определяются по объединению EN+RU слоёв (позиция `;` = RU `ж`, `,` = RU `б` и т.д.).
- **D-15:** Цифры внутри слова входят в диапазон замены и идут через таблицу тождественно (цифры одинаковы в обеих раскладках); направление определяется только по буквам. `ghbdtn2026` → `привет2026`. Нейтральные символы «смешанным» слово не делают.

### Смешанное слово
- **D-16:** Слово с буквами обеих раскладок (`gfbпривет`) в Фазе 2 не трогаем вовсе — тихий отказ. Порог строгий: любая одна «чужая» буква делает слово смешанным. Полная семантика «только чужие буквы относительно последней раскладки» — Фаза 3 (CORR-06, Q-маркер SPEC §4.2). Нейтральные символы (цифры, общая пунктуация) смешанным слово не считают. — **Reversibility:** reversible — правило в логике определения направления

### e2e-матрица v1 (TEST-04)
- **D-17:** Матрица v1 покрывает zenity entry (GTK-класс, уже в стенде Фазы 1: self-focused, AT-SPI-witness) + Chromium (обязателен по ADR-003 — подтверждает фактический fallback-уровень). Терминал отложен: владелец изначально выбрал его в v1, но после подтверждающего вопроса (clipboard-уровень = реализация wl-copy/wl-paste в объёме Фазы 2) снял. — **Reversibility:** reversible — ширина матрицы наращивается
- **D-18:** Набор кейсов v1 — полный словесный: оба направления (`ghbdtn`→`привет`, `привет`→`ghbdtn`), три регистра (`GHBDTN`→`ПРИВЕТ`, `Ghbdtn`→`Привет`, `ghbdtn`→`привет`), слово после пробела (D-13), пунктуация/цифры внутри (D-14/D-15), смешанное слово → не тронуто (D-16). YAML-формат кейсов, отчёт PASS/FAIL, код выхода ≠ 0 при падении — по TEST-04.
- **D-19:** Прогон матрицы живёт на self-hosted GNOME CI-раннере, поднимаемом уже в Фазе 2 (владелец осознанно выбрал это вместо только-локального `mise run`). Требования к раннеру — из STACK: GNOME-сессия, пользователь в группе `input`, python3-gi + gir1.2-atspi. — **Reversibility:** costly — инфраструктура CI; сворачивание позже ломает регрессионный контур

### Тихий отказ и наблюдаемость
- **D-20:** При молчаливой отмене коррекции (сверка не сошлась / смешанное слово / буфер пуст) пользователь не видит ничего; демон пишет причину отказа в журнал (INFO, причина без содержимого слова). «Abort, не мусорить» — без визуального шума.
- **D-21:** Детали УДАЧНЫХ коррекций (исход→результат, уровень лестницы, latency) — только в `-debug`; на INFO — только счётчики. Приватность по образцу Фазы 1 (README уже описывает keystroke-трассировку как -debug-only).

### Claude's Discretion
- Точная таблица «буквенных клавиш» (объединение EN+RU слоёв по позиции) — исследователь сверяет с генератором таблиц Фазы 1 (`layouts/`); принцип задан D-14.
- Механика «буфер помнит последнее слово после пробела» (хранить одно слово vs хранить всю фразу с указателем) — планировщик выбирает с прицелом на CORR-02 (фразы, Фаза 3).
- Порядок задач, разбиение на планы, детали self-hosted раннера (runner-группы, метки, триггер manual-dispatch vs на-PR) — исполнитель.

</decisions>
