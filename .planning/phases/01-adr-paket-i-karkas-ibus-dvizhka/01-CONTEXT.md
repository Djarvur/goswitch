**Gathered:** 2026-09-10

<domain>
## Phase Boundary

Фаза 1 закрывает все архитектурные развилки пакетом решений (ADR) и строит каркас демона `goswitchd` как IBus input method engine на godbus: регистрация компонента (`_RegisterComponent` через собственный адаптер `engine/`), приём клавиатурных событий как активный источник ввода, структурированные логи с debug-трассировкой, устойчивость (recover-шим, цикл перерегистрации после рестарта ibus-daemon), транзит обычного набора без захвата клавиатуры (совместимость с keyd/xremap), скелет e2e-стенда (ydotool → лог) и headless CI (golden-таблицы ЙЦУКЕН↔QWERTY через `go:generate`, unit-корпус FSM хоткеев). Коррекция текста и переключение раскладки реализуются в фазах 2–3; в фазе 1 — только решения о них и каркас, который их видит в логе.

</domain>

<decisions>
## Implementation Decisions

### Механизм переключения раскладки (Decision #1)
- **D-01:** Механизм выбирается экспериментом в фазе 1, до кода коррекции/переключения. Проверочный вопрос: «может ли демон приказать системе GNOME переключить активный источник ввода?» Да → two-engine (два источника goswitch-en/goswitch-ru с XKB-раскладками us/ru; нативный значок, Super+Space, MRU). Нет → внутренний флип (один движок с `<layout>us</layout>`, EN/RU — внутренний режим, как в работающем прототипе владельца). Результат фиксируется ADR. — **Reversibility:** reversible — выбор происходит в самом начале фазы, до реализации зависимого кода
- **D-02:** Обходные пути (хаки) для программного переключения источника допустимы при условиях: без root, без правки системных файлов, работает на Ubuntu 24.04 GNOME Wayland, переживает перезагрузку. Пример кандидата: имитация нажатия Super+Space. — **Reversibility:** reversible
- **D-03:** Если победит внутренний флип (вариант B) — «один хозяин»: в источниках ввода остаётся только goswitch, системные us/ru убираются; Right Shift — единственный переключатель; Super+Space ничего не переключает. Двойное состояние исключено. — **Reversibility:** costly — это пользовательский контракт модели переключения (UX + документация + e2e-кейсы); смена на two-engine позже потребует переучивания пользователей и переделки e2e

### Тайминг тапов Right Shift
- **D-04:** Классическая схема с ожиданием: после тапа Right Shift демон ждёт окно различения, и только потом выполняет действие (одиночный → переключение, двойной → слово, тройной → фраза). Владелец осознанно отклонил Caramba-схему «мгновенный свитч на первый тап» и разные клавиши. — **Reversibility:** costly — FSM хоткеев, дефолты конфига, переформулировка NFR и тайминговые e2e-кейсы завязаны на схему
- **D-05:** Окно различения тапов по умолчанию 300 мс, настраивается в YAML. NFR о скорости переформулируется (spec-delta к §5 спеки): «действия без ожидания — <50 мс; действия Right Shift — не дольше окна различения». — **Reversibility:** reversible — значение в конфиге

### Сброс буфера (CORR-09)
- **D-06:** «Клик мыши» убирается из триггеров сброса буфера (невыполнимо на уровне метода ввода — клик не доходит до IBus). Вместо него два механизма: (1) обязательная сверка перед коррекцией — буфер должен совпадать с текстом непосредственно перед курсором (surrounding text); не совпало → молча ничего не делать («abort, не мусорить»); (2) best-effort сброс буфера по скачку позиции курсора в surrounding text там, где приложение его полностью сообщает. Оформить как spec-delta к §4.3 спеки. — **Reversibility:** reversible

### Открытые решения (требуют владельца)
- **OPEN-01 (MACR-01):** Замена Super+Буква → Ctrl+Буква по приложениям — владелец не ответил при обсуждении; решение НЕ принимать без него. Рекомендация исполнителя (не решение): вынести в v2 через spec-delta, в документацию добавить рецепт настройки через keyd (у владельца уже стоит; keyd делает перелинковку по приложениям штатно на правильном уровне; движок IBus не имеет надёжного способа определить приложение, а Super часто перехватывается GNOME раньше метода ввода). Вопрос вернуть на утверждение ADR-пака (критерий фазы 1, гейт M0 «ревью владельца»). До решения планировщику MACR-01 не реализовывать и не планировать код.

### Инженерные директивы владельца (2026-09-10, выданы после обсуждения, до кода — BIND)
- **D-07:** Строгий TDD для всего кода: каждая задача на поведение — red (падающий тест) → green (минимальная реализация) → refactor. Планы размечают задачи `type: tdd` там, где поведение, а не конфиг/доки.
- **D-08:** Каждая итерация (задача) завершается только при зелёных: `go build ./...` И `go test -race ./...` И `golangci-lint run`. Это инвариант конца каждой итерации, не финальный гейт фазы. — **Reversibility:** costly — гейт вшивается в verify-блоки всех задач и CI; отключение позже = деградация качества
- **D-09:** Проверочные сценарии — задачи mise (`mise.toml`: build/test/lint/ci/e2e), НЕ Makefile. Инструменты (go, golangci-lint) управляются mise per-project (`[tools]`) — golangci-lint ставится через mise, отсутствие в системе больше не основание для отклонения. — **Reversibility:** reversible
- **D-10:** golangci-lint с максимально строгим конфигом с Фазы 1: `.golangci.yml` адаптируется с эталона владельца `~/DiskD/W/Djarvur/ass-guard-agent/.golangci.yml` (v2; `linters.default: all`; disable только с построчным обоснованием; depguard deny `unsafe`; gocyclo 20 / cyclop 15 / gocognit 30; lll 120; gocritic diagnostic+performance+style; revive; dupl 120; nestif 6; formatters gofmt+goimports с `local-prefixes: github.com/Djarvur/goswitch`). Прежнее отклонение «golangci-lint отложен» (CONVENTIONS.md, round-1 ревизии) ОТМЕНЕНО. — **Reversibility:** costly — конфиг и гейты входят в CI и все verify-блоки
- **D-11:** GitHub Actions создаются с Фазы 1 и поддерживаются актуальными: (a) PR sanity — build + vet + golangci-lint + test -race + tidy-diff + govulncheck на push/PR; (b) периодическая проверка обновлений зависимостей (scheduled job / dependabot — механизм выбирает план); (c) периодические проверки безопасности (scheduled govulncheck + зависимости). — **Reversibility:** reversible
