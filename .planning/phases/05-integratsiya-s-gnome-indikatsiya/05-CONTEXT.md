# Phase 5 Context — Интеграция с GNOME: индикация и двухисточниковое переключение

## Почему эта фаза существует (живые находки 2026-09-27/28)

1. **Индикатор не виден вообще**: GNOME 46 показывает панельный индикатор ввода
   ТОЛЬКО при 2+ источниках в `org.gnome.desktop.input-sources sources`. С
   единственным `('ibus','goswitch-en')` его не показывает никакая настройка
   (`show-all-sources` — ключ про диалог настроек, проверено по gschema.xml;
   хэндовер в install был добавлен и откачен). Panel-свойства IBus
   (RegisterProperties/UpdateProperty + icon_prop_key, реализованные в
   260927-way) рендериться некуда — механизм остаётся в коде, но не решает
   проблему индикатора.
2. **Владелец предложил и утвердил архитектуру** (сессия 2026-09-28): включить
   ДВЕ раскладки в GNOME, отобрав у него переключение по клавишам (уже
   сделано: install очищает оба чорда `org.gnome.desktop.wm.keybindings
   switch-input-source[-backward]`, uninstall восстанавливает), раскладки
   добывать из GNOME, переключать у себя.
3. **Переключение сейчас — внутренний флип** (ADR-001 Option B): демон
   держит mode EN/RU внутри, XKB-layout всегда 'us', GNOME о режиме не знает.

## Решения владельца (locked, не пересматривать)

- **D-52 (2026-09-28): двухисточниковая схема.** sources = два goswitch-движка,
  флип = `SetGlobalEngine` на шине IBus (прямой D-Bus call, не subprocess),
  индикатор нативный. Это ревизия ADR-001 (Option B → Option A) — оформить
  как ADR-006 с живыми находками как обоснованием.
- **D-53 (2026-09-28): источники обязаны быть `('ibus',...)`.** xkb-источники
  обрабатываются mutter/XKB МИМО ibus-движков — демон не видит ни одной
  клавиши. Доказано живьём: при отвале движка GNOME переписал sources в xkb
  и ввод молча шёл мимо goswitch.
- **D-54 (2026-09-28): install НЕ хардкодит пару en/ru.** Он читает текущие
  sources ПОЛЬЗОВАТЕЛЯ и оборачивает каждый источник пары в goswitch-движок
  его раскладки: `('xkb','us')→('ibus','goswitch-en')`,
  `('xkb','ru')→('ibus','goswitch-ru')`. XKB-layout лежит внутри EngineDesc
  каждого движка (механизм уже есть). «Раскладку выбирает пользователь» —
  install лишь оборачивает выбор.
- v1 оборачивает ТОЛЬКО пару us↔ru (таблицы конвертации только
  ЙЦУКЕН↔QWERTY): другая пара — честный отказ/предупреждение. Произвольные
  пары из xkb-данных — веха v1.1 (Phase 7+/milestone v1.1 вместе с
  автокоррекцией).
- Пользователь может сам добавить третий xkb-источник — переключение на него
  честно выводит из-под goswitch (ожидаемое поведение, задокументировать).
- Правило флипа после коррекции (2026-09-28, уже в коде): режим = скрипт
  результата; в двухисточниковой схеме это «активным становится движок
  скрипта результата».

## Технические заметки для планировщика

- **SetGlobalEngine**: метод `org.freedesktop.IBus` на ibus-соединении демона
  (engine/conn.go держит conn в serve; нужен seam —например,
  `engine.Config.BindSwitcher func(func(name string))`, вызываемый при
  подключении поколения, main проводит его в actor). Латентность — локальный
  D-Bus call, бюджет <50 мс. Само-реактивация (260927-sy8) уже использует
  gsettings+`ibus engine` — при двух источниках реактивировать надо АКТИВНЫЙ
  источник (обобщение `activate.IfOwned`: current индекс → имя движка).
- **Синхронизация состояния**: единственный переключатель — goswitch
  (GNOME-чорды очищены), но mutter может сам менять активный источник (клик
  по индикатору!). Нужен listener: `gsettings monitor
  org.gnome.desktop.input-sources current` (процесс уже исследован в STACK)
  или наблюдение `org.freedesktop.IBus.GlobalEngineChanged` — режим демона
  подтягивается под фактический активный движок (FocusIn тоже сигнал).
- **Режим двигателя = имя движка**: modeRU-ветка feedKey коммитит кириллицу —
  при двух движках режим должен следовать за активным движком (или остаться
  внутренним, но синхронным). Продумать сброс контекста: SetGlobalEngine
  даёт FocusOut/FocusIn — буфер/FSM сбрасываются (семантика «переключение
  раскладки сбрасывает контекст» — та же, что в GNOME).
- **install**: снапшот sources уже есть; обёртка пары → новая логика
  takeoverSources; ASVS-дисциплина (fallback, shape-check, verbatim restore)
  сохраняется; selfcheck (`ok input-source`) обновить под два источника.
- **e2e**: кейсы переключения (layout-single, super-space-alive, combo)
  завязаны на журнал `mode` записей — сохранить контракт записи; добавить
  кейсы видимости индикатора НЕ надо (не наблюдаемо без глаз) — живая
  проверка владельцем; кейс «клик по индикатору переключает — демон
  синхронизируется» — желателен.
- **Что НЕ трогаем**: panel-свойства (260927-way) оставить как есть
  (безвредны, могут рендериться в других шеллах); Super+Space чорд и
  одиночный Shift — те же жесты, меняется только механизм исполнения флипа.
- **Риски**: гонка SetGlobalEngine против набора (флип в момент набора —
  клавиша может уйти старому движку: рассмотреть сброс FSM до вызова);
  поведение mutter при программной смене current; производительность
  переключения (D-Bus roundtrip) — измерить в e2e.
